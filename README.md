# ClinicalDataFlow

ClinicalDataFlow is a personal data engineering project that demonstrates an end-to-end workflow for processing synthetic healthcare data.

The project was built to practice working with healthcare data, APIs, Python, PySpark, data validation, and structured storage while following patterns similar to real-world data engineering pipelines.

## Overview

The pipeline is designed to take clinical data from a source system, preserve the raw data, transform it into a cleaner structure, validate important fields, and produce processed datasets that are easier to work with for analytics or downstream applications.

The project uses synthetic healthcare data rather than real patient information.

## Pipeline

The general workflow is:

```text
Healthcare Data Source
        |
        v
   API Ingestion
        |
        v
    Raw JSON
        |
        v
 PySpark Processing
        |
        v
 Data Validation
        |
        v
 Processed Parquet
```

Raw data is kept separately from transformed data so that the original source records remain available if the pipeline needs to be reprocessed or debugged.

## Key Features

- Python-based data ingestion and processing
- Healthcare data retrieved through APIs
- Raw JSON data retention
- PySpark transformations
- Nested healthcare data processing
- Data quality and validation checks
- Duplicate and missing-value checks
- Date and field validation
- Transformation of nested structures into analytics-friendly formats
- Parquet output for processed datasets
- Docker configuration for reproducible development

## Data Processing

The transformation process reads raw healthcare records and prepares them for downstream use.

Some of the processing includes:

- Parsing nested JSON structures
- Extracting relevant clinical fields
- Converting values into appropriate data types
- Exploding nested arrays when necessary
- Standardizing date fields
- Identifying missing or invalid values
- Checking for duplicate records
- Creating validation flags for data quality issues

The goal is to separate ingestion, transformation, and validation so each part of the pipeline can be tested and modified independently.

## Why I Built This

I built ClinicalDataFlow to get more hands-on experience designing a data pipeline from beginning to end rather than only working on individual parts of an existing system.

I chose healthcare data because I previously worked with healthcare integrations and wanted to build a project that combined that experience with Python, PySpark, APIs, and modern data engineering practices.

## Disclaimer

This project uses synthetic data for development and demonstration purposes. It does not contain real patient information or protected health information (PHI).
